# Creative UI Director

Use when building or improving pages, dashboards, components, Mini Apps, landing pages, game UI, visual tools, onboarding, or any interface that should feel intentional rather than generic.

## Direction Brief

Before coding, produce a compact direction brief:

- Product job: what the screen helps the user accomplish
- Primary user: what they need to see first
- Interface tone: operational, playful, premium, calm, technical, editorial, or another explicit tone
- Visual hierarchy: primary action, secondary actions, tertiary data
- Memorable detail: one design decision that fits the domain
- Constraints: existing components/tokens, accessibility, performance, mobile, runtime proof

## Implementation Rules

- Build the usable experience first, not a marketing wrapper, unless the user explicitly asks for a landing page.
- Start with existing components and tokens.
- Use real product data shapes, states, and constraints.
- Design for loading, empty, error, disabled, success, and permission-denied states.
- Verify responsive constraints and text fit before claiming the UI is done.

## Review Output

Report:

- chosen direction
- what changed visually and why
- accessibility checks
- responsive/browser proof
- remaining design risks or follow-up polish
