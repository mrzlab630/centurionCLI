# W4 isolated candidate delivery

Product: `3.0.0-rc.2`. Canonical load map:
`integrations/codex-legion-kit/scripts/lib/surface-config.mjs`.
The existing installers share staged owned-file installation. Core selects one
functional entrypoint; planner/context abilities are incorporated. Domain and
maintenance selection are explicit. Excluded skill entrypoints and legacy
upstream delegation paths do not enter the installed delivery bundle.

Installed-chain receipts enumerate all package file hashes and instruction
candidates, including native instructions, plugin agents/output style, SOUL notes
and bundle YAML. `liveLoadedChainProven=false` deliberately distinguishes package
readback from actual native runtime consumption. A missing adapter capability
receipt records exclusion. Binary/config/route/adapter changes invalidate recorded
capability; no dispatch probe or automatic update is part of installation.

Cold/owned-upgrade, selection retirement, conflict preservation and rollback are
covered by the existing `tests/install-owned-files.test.mjs`. Open Design's
cross-client fixture uses explicit isolated install targets and a mock production
backend, with no live Hermes CLI startup. Reference fixtures resolve paths from
their module, independent of caller cwd. Browser/image/provider proof remains live
acceptance, not the offline fixture's claim.

N5 remains subject to independent authority review. N6 whole-kit validation needs
W2/W3 integration and root proof. Python runner/contract modules and regressions
are outside W4 ownership; source packaging of them is not runtime acceptance.
Native isolation/flags/schema, live loaded-chain priority, no-write correction,
pilot and release approval remain unaccepted where their evidence is missing.
Foreign/global legacy homes without ownership receipts require separate migration
authority; this candidate never silently rewrites their settings or instructions.
