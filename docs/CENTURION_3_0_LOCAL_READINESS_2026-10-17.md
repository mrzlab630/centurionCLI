# CENTURION 3.0 — исправления и локальная готовность, 2026-10-17

## Повторное окно r2 (17 октября)

После разрешения владельца «ок. делай» проведено новое изолированное окно.
Q1–Q6 приняты с фактическими native/tool доказательствами; P1 принят. P2
остановлен после сохранённого отказа первого ревью и одной owner-реконсиляции:
второй Opus review корректно вернул `pass` и пустые `findings`, но его canonical
result был отклонён контроллером, потому что disposable review order разрешал
только `custody/**`, хотя результат ссылался на неизменённые product artifacts.
Это дефект подготовки области read-only заказа. Review-3 и повтор продукта не
запускались. P3–P6 не приняты и не запускались.

Исправленная native-схема reviewer теперь требует `pass` с пустыми findings,
`fail` с непустыми findings, а `blocked` оставляет список findings. Регрессия
builder прошла 22 группы; полный Hermes smoke после интеграции прошёл. Два
последующих source-review запроса Claude/Opus остановлены по 300-секундному
локальному timeout без вердикта, поэтому независимая приёмка исходников
отсутствует. Установка в рабочие homes не выполнялась.

**Рабочая установка не выполнена. Кандидат остаётся 3.0.0-rc.1.**
Владелец разрешил закончить работу, проверить её через Claude и установить
локально при готовности. Условие готовности пока не выполнено: N7 неполон;
повторное независимое ревью исправленного кода завершилось без вердикта.
Работа ведётся в `feat/centurioncli/v3-implementation`.

Это актуальное продолжение [отчёта реализации](CENTURION_3_0_IMPLEMENTATION_REPORT.md)
и [плана 1.5](CENTURION_3_0_IMPLEMENTATION_PLAN.md). Исторические результаты не
переписаны. Машинная сводка и сохранённые ответы находятся в
[каталоге этого прохода](reviews/centurion-3.0-implementation/oct17/acceptance.json).

## Исправления

1. **Запуск Claude через локальный прокси.** Gateway сохраняет обе переменные
   `ANTHROPIC_BASE_URL` и `ANTHROPIC_DEFAULT_OPUS_MODEL`; до запуска проверяет
   локальный endpoint и совпадение модели с утверждённым routing. `.bashrc`
   автоматически не исполняется. Credentials и глобальная конфигурация не меняются.
2. **Native ответ Claude.** CLI может вернуть `structured_output` вместе с
   текстовым `result`. В режиме native schema выбранным источником остаётся
   structured object. Его отсутствие, неверная идентичность или ошибка формата
   не разрешают переход к тексту и повтор продукта. Обновлены обе действующие
   регрессии этого поведения.
3. **Report-only режим.** Добавлен явно выбираемый `native-profile-readonly`:
   pinned CLI/bwrap/profile/settings/endpoint, существующий профиль CLI только
   для чтения, запись только в scratch, выключенные local tools/MCP/hooks.
   Обычная ошибка sandbox не допускает запуска Claude вне sandbox.
   Проверяются executable permissions до расходования report attempt;
   empty mount target после bwrap распознаётся отдельно от изменённого профиля.
   Режим остаётся выключенным без controller-approved Q6 receipt; новая ветка
   сама не выдаёт разрешение и не объявляет P6 пройденным.
4. **Завершение архитектурной миссии.** Явное `task.completionAction=advisory`
   фиксируется в authority при инициализации. По умолчанию остаётся `product`.
   Консультация не закрывает обычную продуктовую задачу; продуктовый запуск
   не разрешён для advisory-only задачи. Итоговый controller proof сохранён.
5. **Установка в существующие homes.** Установщик и аудит больше не обходят
   весь пользовательский home и не присваивают ownership конфигурации/секретам.
   Они работают с точными путями файлов пакета. Legacy-миграция требует
   `--migration-record` с проверенными preimages; модифицированные и неизвестные
   целевые файлы отклоняются. Замены отдельных файлов сохраняют runtime-соседей.
   Пользовательский текст native instructions можно явно сохранить рядом с
   управляемым блоком. Это сохраняет байты, но не доказывает совместимость правил.
6. **Замечание Claude к миграции.** Подменённые границы `preservedInstruction`
   позволяли пропустить аудит управляемого содержимого. Дефект воспроизведён;
   общий validator теперь проверяет маркеры, непустое тело и сохранённые области
   как при аудите, так и при обновлении.

Advisory closure и установщик реализованы двумя ограниченными заданиями
GPT-6.1 Sol/xhigh; контроллер проверил результаты и выполнил интеграционные
исправления. Изменения рабочих homes исполнителям не поручались.

## Независимая проверка Claude

Native Claude CLI 2.1.224 запущен через существующий локальный прокси с
`claude-opus-5-5`, effort `high`, без инструментов и с read-only native profile.
Запрос и ответ связаны хешами исходников. Новый пароль, ключ или `/login` не
использовались. Native профиль может сам предоставлять клиентскую auth-информацию;
отсутствие переданного нами ключа не означает отсутствие auth в HTTP-запросе.
Requested/reported model совпали; это не независимая аттестация модели upstream.

Первый ответ — `REVISE`, пять замечаний. Контроллер проверил достижимость каждого:

| Замечание | Решение по фактическому коду |
| --- | --- |
| F1: fallback с native object на текст | Не воспроизведено: ветки `if/elif` исключают этот переход; production caller не передаёт `native_override=False`. Регрессия отклоняет missing structured при валидном text. |
| F2: silent fallback при недоступном bwrap | Не воспроизведено: запускается абсолютный argv sandbox, ошибка останавливает child. Добавлена ранняя проверка executable permissions, чтобы не расходовать попытку на такой отказ. |
| F3: отзыв advisory authority не проверяется для accepted task | Не воспроизведено на принятом advisory state: старый digest отвергнут; после пересчёта digest запрет action всё равно обнаружен. |
| F4: preserved ranges обходят управляемый аудит | Подтверждено для prior receipt и исправлено. Объяснение через migration record было неточным; текущее содержимое wrapper всегда вставлялось. |
| F5: malformed local URL | Внешний hostname и непустые credentials уже отклонялись. Пустой userinfo `http://@localhost:8317` действительно допускался; теперь отклоняется вместе с whitespace. |

Второй запрос получил актуальные исходники и результаты разбора. Через 240 секунд
он остановлен по локальному timeout; stdout пуст, вердикта нет. Это не `ACCEPT`.
Удалённая отмена вычисления у поставщика не доказана. Лимит этого прохода ревью —
два запуска, дополнительных автоматических повторов не было.

## Почему N7 и установка остаются закрыты

Новое capability-окно открыто по поручению владельца; прежняя неудачная попытка
сохранена в счётчике. В итоге **8/8 запусков**: один исторический, два Q6 в этом
окне и Q1–Q5. P1–P6 не запускались. Два source-review запуска выше относятся к
отдельному ограниченному code-review, не являются повторами capability probes и
не закрывают их критерии.

| Проба | Наблюдение |
| --- | --- |
| Q6, пустой profile | Обе route-переменные недостаточны: клиент отказал до API. |
| Q6, native profile read-only | Успешный native ответ, API activity, `writeSucceeded=false`, контрольный файл без изменений, telemetry server search/fetch = 0. Raw result ошибочно содержит старый label Q6-local-proxy; folder/order/ledger однозначно связывают его с Q6-native-profile. Исторический raw не исправлен. Это ограниченное наблюдение; полноценный Q6 receipt и P6 не приняты. |
| Q1 | В изолированном Hermes не была зарегистрирована named custom provider entry; отказ инициализации до API. |
| Q2, Q3 | Модель ответила, но команда чтения не выполнилась: служебный mount registry native sandbox оказался read-only внутри внешнего bwrap. |
| Q4 | Native profile смонтирован в HOME, а `CLAUDE_CONFIG_DIR` указывал в другой каталог; отказ до API. |
| Q5 | Тот же отказ native sandbox; Playwright не появился в модели. DOM/screenshot/vision round-trip не состоялся. |

Это ошибки подготовки изолированного пилота, а не доказательство слабости моделей
или неработоспособности локального прокси. В подготовке устранены/уточнены причины:
named Hermes provider с Responses; profile в точном Claude config dir;
нативный Codex sandbox без несовместимого вложенного bwrap; существующие cached
MCP/Chromium entrypoints вместо неявного скачивания через npx в пустой HOME.
Приватный `/tmp` сам по себе проблему вложенного sandbox не решил: после него
воспроизведён namespace denial; native sandbox отдельно прошёл.

Подготовлен disposable сценарий P1–P6 с фиксированными входами, заказами,
схемами, независимым review и финальным proof. Проверена форма заказов и запрет
запуска при отсутствующих Q receipts/исчерпанном бюджете. Сценарий **не прошёл
live mission validation**. Перед следующим запуском нужны новые изолированные
Codex fixtures вне `/home/mrz` ancestry и проверка фактически загруженных инструкций.
Новых тестовых служб/benchmark/dashboard в продукт не добавлено.

## Оставшийся порядок

1. Зафиксировать новое разрешённое окно N7 с сохранением всей истории и счётчиков;
   лимит не обнуляется автоматически. До inference выполнить исправленный
   deterministic preflight каждого выбранного клиента и инструмента.
2. Подтвердить Q1–Q6 на конкретных launcher/config; выдать Q6 receipt только по
   достаточному no-write/no-side-effect доказательству. Затем выполнить P1–P6,
   включая настоящий независимый reviewer и report recovery без product replay.
3. Получить завершённую независимую проверку финальных байтов; сверить review
   binding, общую приёмку и остаточные риски.
4. Только после приёмки N7 — точная миграционная ведомость, свежие резервные
   копии, проверка совместимости пользовательских правил и безопасное завершение
   активных заданий. Далее установка, readback, локальный canary и rollback proof.

Разрешение владельца на такую условную установку уже имеется; заново спрашивать
его ради тех же действий не требуется. В этом проходе установки, live migration,
перезапуска Hermes, публикации, push и release tag не было.
