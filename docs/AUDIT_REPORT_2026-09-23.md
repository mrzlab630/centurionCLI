## Подтвержденные остающиеся риски

### P1 — установленная версия отстает от checkout

`~/.agents/skills/velites/scripts/recon.py` на этом хосте старее исходника. До исправления установленный скрипт без `PYTHONPATH` не находил `libs`, а с действующим `PYTHONPATH` загружал старый `~/.codex/libs/legion_core.py`; эта копия устанавливает `ssl._create_unverified_context` как контекст HTTPS по умолчанию (`~/.codex/libs/legion_core.py:15-19`). Исправление есть только в checkout. Проверка установленной Claude-поверхности показала расхождение одного файла плагина и 31 каталога навыков. **Усиление:** подготовить отдельное контролируемое обновление установленных артефактов с резервной копией, сверкой хешей и проверкой запуска/TLS после установки. Не считать тест checkout доказательством исправления установленной версии.

### P1 — прямой путь runner обходит квитанции Result Gateway

`agent_contract_runner.py:1129-1132` отвергает прямой `--mode run` только для Astra advisory. Для других Codex/Claude-заказов прямой путь остается; это прямо отмечено в `agent-contract-runner/SKILL.md:78`. **Усиление:** требовать Gateway и проверяемые start/closure receipts для всех внешних Codex/Claude-диспетчеризаций либо доказать отдельный эквивалентный контрольный путь.

### P1 — цепочка заказов не связывается проверяемыми байтами

`agent-contract-runner/SKILL.md:47-50` указывает, что runner пока не проверяет межзаказные ID, хеши и frozen manifest для цепочки advisory → implementation → review → closure. Хеши одного запуска Gateway существуют, но не заменяют проверку всей цепочки. **Усиление:** зафиксировать байты принятого артефакта/manifest и проверять их идентичность в следующем заказе и перед окончательным закрытием.

### P2 — `evidenceNeed` не повышает маршрут

Политика говорит, что потребность в доказательствах может повышать модель/усилие (`overrides/ADAPTIVE_MODEL_ROUTING_POLICY.md:28-29`). Код проверяет значение поля (`review_ladder.py:334-336`), но не использует его в `_requires_sol`, `_minimum_codex_effort` и `minimum_profile` (`review_ladder.py:168-215`). При остальных одинаковых низкорисковых метаданных значения `low` и `high` дали одинаковый V0/Luna/`none`. **Усиление:** явно определить влияние поля на минимумы и добавить парные регрессии для `low`/`high`.

### P2 — V0 опирается на утверждения о будущих доказательствах

До делегирования V0 требует `requiredArtifactsPass=true` и `requiredProofsPass=true` (`review_ladder.py:43-50,159-165`), хотя реальные proof-команды выполняются после исполнителя (`agent_contract_runner.py:1098-1105`). Итоговая проверка существует, но предварительное решение отказаться от независимого ревью опирается на самоутверждение. **Усиление:** отделить проверяемые до запуска свойства задачи от итоговых результатов proof/artifact и сохранить fail-closed реакцию на их провал.

### Ограничение — V3 намеренно заблокирован

Даже при `specialistGate.approved=true` `review_ladder.py:415-423` возвращает ошибку: доверенного источника проверки approval нет. Это задокументированное ограничение, а не регрессия. **Усиление:** добавить независимый источник и проверку approval до включения V3; не заменять их полем, заполненным самим заказом.

### Операционный риск — корневой установщик не транзакционный

`install.sh` копирует файлы непосредственно в пользовательские каталоги и не обеспечивает атомарное переключение всей установки. Его резервная копия Claude home не является доказанным откатом остальных целевых каталогов. **Усиление:** staged-установка, проверка хешей и режимов, затем переключение с проверенным откатом. Это отдельная работа до применения исправлений на живой машине.

### Предел анализа — HARUSPEX не является полным SAST

`skills/haruspex/scripts/scan_code.py:14-30` ищет построчные regex-совпадения только в перечисленных расширениях и читает текст с `errors='ignore'`. Успешный проход означает завершение этого ограниченного поиска, а не отсутствие уязвимостей или полное покрытие исходников. **Усиление:** явно отражать покрытие и для требуемых языков дополнять проверку анализом синтаксиса/потоков данных.
