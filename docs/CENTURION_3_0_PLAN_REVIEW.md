## 2. Как выполнено ревью Claude

Пользователь явно запросил Claude через локального провайдера. Whitelist-параметры найдены в `/home/mrz/.bashrc`: `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-5-5`, `ANTHROPIC_BASE_URL=http://127.0.0.1:8317`. Каталог вернул модель, затем выполнен реальный `POST /v1/messages`, без credentials. Catalog/HTTP 200 отдельно не считаются завершённым ревью.

Использован ограниченный `CLAUDE_ORDER v1`: read-only входы, `ExecutionDecision`, свежий artifact namespace и snapshot вне рабочей области. Модель получила текст пакета через API; tools не передавались, доступа к файловой системе у вызова не было. Программный контроллер сохраняет raw response и проверяет результат штатным валидатором/guard. Это применение [evocate-ad-opus](/home/mrz/.agents/skills/evocate-ad-opus/SKILL.md) и репозиторного [claude-order](../integrations/claude-legion-kit/plugin/skills/claude-order/SKILL.md); локальная ссылка на установленный skill не является частью runtime-поставки.

Запрошены Opus 5.5 и effort high. Provider-reported модель проверяется в receipt. Это доказательство сообщённого маршрута, не независимая аттестация внутренней модели поставщика. Никаких секретов/домашних конфигураций сверх двух явно указанных несекретных параметров в пакет не включалось.

## 4. Проверка и фиксация версии плана 1.0

Для r2 подготовлен только исправленный самодостаточный план, без исторических документов. Это одна адресная проверка внесённых изменений тем же Claude, не цепочка разных ревизоров. Вызов r2 завершился `max_tokens`: весь лимит 9 000 output tokens ушёл на thinking, текстового заключения нет. HTTP 200 и модель `claude-opus-5-5` не превращают этот вызов в пройденное ревью.

Технический повтор r3 использовал те же bytes кандидата, ту же модель и effort `high`, но output budget 24 000. JSON Schema задана для результата; инструменты отсутствовали. Ни состояние проекта, ни содержание плана между r2 и r3 не изменены. r3 завершился `end_turn`, provider сообщил `claude-opus-5-5`; canonical guard прошёл: `ok=true`, `productChanged=[]`, `scopeViolations=[]`, `failures=[]`. Это полноценный результат проверки плана, а не только успешный HTTP.

Кандидат r2: SHA-256 `f8bf1c05470289eb33163bf074fea90e6a706899f649c0327b8ca872ac63878c`.

Последующие изменения ограничены этими пятью уточнениями; нового этапа или модели не добавлено. Повторного полного Claude review после этих правок не запускали. Поэтому здесь **не утверждается ACCEPT Claude для окончательных bytes**: Claude проверил замороженного кандидата, а владелец проверил исправления его findings и принял доработанный план для фиксации. Остаточные ограничения r3: время probes может израсходовать общий бюджет раньше завершения всех миссий; это предусмотренная остановка с неполным пилотом, не повод для бесплатного продолжения. `mission-prep` остаётся советником skills и требует восьми regression cases, уже включённых в N2. Финальный Claude не перечитывал первичные источники — их сверил владелец (§1). Реальные маршруты/изоляция/rollback доказываются будущими N7/N8, а не этим документом.
