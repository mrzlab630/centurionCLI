# CENTURION 3.0 — наблюдение длительных работ, 19 октября 2026

Продолжение [пилота r4](CENTURION_3_0_PILOT_2026-10-18_R4.md) по прямому
указанию владельца: работа модели может занимать часы; длительность сама
по себе не должна завершать процесс. Ветка — `feat/centurioncli/v3-implementation`,
база изменений — `dcd8056`. Исторические миссии и receipts не изменяются.

## Поведение

Новые заказы policy 3.0 используют `launch.timeoutSeconds: null`, новые миссии —
`budget.deadlineAt: null`. При подготовке новой миссии пропущенный deadline
получает null; загрузка сохранённого state требует явного поля. Существующие
конечные сроки сохраняются. Null не разрешает устаревший direct dispatch.

Gateway каждые 30 секунд записывает `process_observed`: PID/startTicks/bootId,
совпадение identity, elapsed, размер вывода и длительность тишины. Последнее
наблюдение сохраняется в существующем intent; при пропущенном `--events`
используется `events.jsonl` в пространстве артефактов заказа. Для итогового
proof последнее наблюдение также остаётся в intent. Это опрос состояния,
а не новый запрос модели и не подтверждение продуктивного прогресса.

Тишина, закрытые stdout/stderr при живом child и превышение прежнего времени
ожидания не вызывают остановку или повтор работы. У report recovery и final
proof в этом режиме нет прежних неявных 120/3600 секунд. Старые wall-budget
aliases исключаются только из advisory-проекции null-миссии; approved authority,
её hash, лимиты запусков и попыток сохраняются.

Явная отмена — SIGTERM/SIGINT процессу Gateway, владеющему заказом. Внешняя
правка JSON не является каналом отмены: единственный writer удерживает lock.
При отмене или ошибке остаётся ограниченный cleanup: TERM до 10 секунд,
общий stop reserve до 30 секунд, не позднее явно конечного mission deadline.
Чтение pipes продолжается во время остановки. При сбое фиксации identity
аварийная очистка использует собственный Popen child; контроль escaped
descendants или отмена вычислений у удалённого provider не заявляются.
Ограничения объёма вывода, доказанный tool-loop, custody и запрет replay остаются.

### Уточнение после `178c348`: безопасный ping для многочасовой работы

Ping каждые 30 секунд дополняет `process_observed` локальным CPU-счётчиком,
изменением вывода и диагностикой `alive_active`, `alive_waiting`, `exited` или
`unknown`. Последнее означает недоступность probe или неподтверждённую identity.
Ошибка периодического чтения `/proc` раньше попадала в аварийную остановку;
теперь она записывается как `unknown`, а следующий ping повторяет диагностику
без остановки или перезапуска child. Первичная фиксация identity, запись
custody и проверка identity перед сигналом остаются обязательными.

Локальный ping не определяет внутреннее состояние удалённой модели.
Используемые CLI adapters не подключают status/heartbeat конкретного запроса
провайдера: `modelStatus` остаётся `unknown`, `hangConfirmed=false`.
Часы тишины, нулевой CPU, общий `/health` и новый тестовый inference не дают
оснований объявлять зависание. Сигнал от провайдера можно использовать только
после проверки его привязки к текущему запросу; без него ожидание продолжается.

Проверка этого уточнения: 24 PASS-группы Gateway и повторный изолированный
Hermes smoke с 13 packaged regressions. Real-child проверки покрывают сбой
probe с восстановлением на следующем опросе, активность CPU без вывода и восемь
**симулированных** часов тишины/EOF без остановки. Это проверка отсутствия скрытого
временного лимита, не восьмичасовой нагрузочный прогон.
Один дополнительный Claude source review через тот же локальный прокси,
без общего timeout: `ACCEPT`, findings `[]`, 56,01 с.
Доказательства этого уточнения — в
[отдельном record](reviews/centurion-3.0-implementation/process-ping-review-2026-10-19.json);
исторические десять reviews и их pins ниже сохранены без изменений.

## Проверка Claude и разбор замечаний

Каждое ревью выполняется через локальный Claude CLI 2.1.224:
`ANTHROPIC_BASE_URL=http://127.0.0.1:8317`,
`ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-5-5`, effort high.
Product mounts read-only, tools/MCP/hooks выключены. Никакого `/login` или
публичного fallback; отсутствие login не свидетельствует о сбое этого маршрута.
Ожидание terminal result не ограничено общим временем; статус фиксируется
каждые 30 секунд. Таймауты операций остановки остаются техническими пределами.

- R4a завершился за 13,01 с: ACCEPT для владения canonical result.
- R4b завершился за 353,16 с: найдено принятие `proof.status=pass` с `exitCode=1`,
  null или bool. Подтверждено и исправлено в runner и builder: pass требует
  именно целого нуля. Для fail/not_run сохранён честный null, если exit не получен.
- T1 принял nullable admission и сохранение конечных сроков.
- T2 за 451,15 с обнаружил пропуск очистки при ошибке identity и блокировку
  чтения pipes во время TERM. Исправления проверены реальными дочерними
  процессами, включая соблюдение общего stop reserve.
- Промежуточные T3 получили неполные фрагменты из-за сдвига номеров строк.
  Утверждение о секундном лимите отвергнуто по полным вызовам: standalone
  `work_timeout(1)` проверяет доступность работы, а его возврат не задаёт timeout
  child. Финальный пакет выбирает целые функции и фактические вызовы через AST.
  Он получил ACCEPT за 15,01 с, включая проверку исправления R4b.
- Одно повторное T2 ошибочно назвало `Popen.kill()` отправкой SIGTERM.
  На Unix это SIGKILL; такое замечание не является основанием для изменения
  process-group policy. Другой ответ положил уже устранённые дефекты в findings
  при ACCEPT. Его raw сохранён; нарушение формы не требует повторять продукт.
- Финальный cleanup-review завершился за **817,29 с** (13 мин 37 с), без
  остановки на прежних 300/600 секундах. Вердикт REVISE: обнаружен вызов killpg
  при обработке остаточного вывода после reap в ветке без reservation.
  Добавлен ровно запрошенный guard `process.poll() is not None`; новая
  real-child регрессия проверяет stream/frame overflow после reap без сигнала
  старой группе. Замечание закрыто владельцем по этому доказательству; отдельный
  model review двухстрочной детерминированной коррекции не запускался.
  Остальные выбранные lifecycle-функции не менялись после review.

Всего в этом продолжении выполнено десять source-review запусков. Исходные
вердикты, разбор замечаний, source pins и точная последняя коррекция сохранены в
[машиночитаемом record](reviews/centurion-3.0-implementation/monitored-review-2026-10-19.json).
Он не переименовывает REVISE в ACCEPT и не является разрешением внедрения.

## Доказательства и пределы

Короткие real-child тесты проверили: silent и EOF-silent child
дольше прежнего лимита; несколько наблюдений; SIGTERM/SIGINT; finite compatibility;
no replay; output/frame caps; восстановление отчёта и итоговый proof без скрытого
таймаута. Матрица proof validator охватывает integer zero, nonzero, null, bool
и float, а также сохранение отрицательного результата без exit code.

Выполнены:

- `regression_agent_result_builder.py`: 26 PASS-групп, включая строгую проверку
  exit code в обоих runner validators и при финализации результата.
- `regression_result_gateway_v3.py`: 22 PASS-группы после последней коррекции
  (предыдущие 21 сохранены отдельным логом). Дополнительно проверены
  ошибка identity после Popen, ошибка identity при чтении вывода, TERM-handler
  с 256 KiB в каждом pipe без потери данных, игнорирование TERM, ограниченный
  выход при отказе identity, отсутствие сигнала чужому процессу и post-reap
  overflow без сигнала старой группе.
- `node integrations/hermes-legion-kit/scripts/smoke.mjs`: успешная изолированная
  установка и 13 packaged Python regressions; mission runner проверен через
  `--mission-only`. Старые direct-dispatch mains не запускались: они выведены
  из активной цепочки. Ограничение test harness в 240 секунд не является
  таймаутом работы исполнителя.

Логи находятся в `.centurion/monitoring-20261019/`; итоговый record связывает
исходники, native ответы Claude, observations, receipts и proof hashes.
Многочасовой production-run не проводился; короткие тесты и статические
проверки не выдаются за такую нагрузку.

**N8 остаётся открытым.** Эти изменения не устанавливаются поверх рабочей среды
до согласования version-scoped AGENTS/SOUL, обновления capability bindings,
настоящего no-new-work drain и installed round-trip. Предыдущий rollback r4
остаётся в силе; source ACCEPT и isolated install не заменяют эти проверки.
